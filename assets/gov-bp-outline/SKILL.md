# 九章骨架：给政府看的 BP / 项目建议书

这不是「商业计划书模板」。九章的顺序本身在讲一件事：**先证明窗口已开，再证明空白存在，最后证明你克制。**

## 章节与每章必答

```
壹 政策依据与时代窗口
贰 要解决的问题
叁 方案总览：闭环
肆 核心机制：分级管控
伍 成长路径：分阶段单边价值
陆 技术架构（必含监管接口层）
柒 政府价值
捌 试点路径（带硬性关卡）
玖 合规红线 + 政策诉求
```

### 壹 政策依据与时代窗口

- 4 张政策卡：每卡 = 文件名 + **文号** + 一句「它开了什么口子」+ 与本项目的关系。
- 收尾一句「窗口期」判断：为什么是现在，晚一年会怎样。
- 要求：**文号一手核过**，标施行日期。核不到写「未核到」，不要凑。

### 贰 要解决的问题

- 双侧痛点：需求侧（谁被卡住）+ 供给侧（为什么现在没人做）。
- 灰色产业「阳光化」框：如果存在灰色替代品，用治理逻辑写——不是禁止需求，而是把需求放进可监管的通道。

### 叁 方案总览：闭环

- 一张横向流程节点图（5 个节点以内），每个节点写清「谁做、做什么、产出什么」。
- 闭环条：数据/凭证如何回流（单向流出＝没闭环，政府第一个问这个）。

### 肆 核心机制：分级管控

- 用分级表格（如绿/金/红三档），每档写清准入条件、数据范围、审批动作、退出条件。
- 尽量对齐已有标准编号（数据分类分级、个人信息保护相关国标），让评审看到「不是自创规矩」。

### 伍 成长路径：分阶段单边价值

- 竖向阶梯图，每级都要有**单边独立价值**：即使只走到这一级、没走到下一级，也已经有人受益。
- 这一章专治「从零冷启动」质疑：没有第一阶段的自证，后面全是空话。

### 陆 技术架构

- 分层色块图（接入 / 处理 / 存储 / 服务 / 监管）。
- **必含监管接口层**：看板、审计取证、红线熔断。政府看架构时先找这一层，找不到就认为不可监管。

### 柒 政府价值

- 3–4 张价值卡，第一张永远是「**可复制的改革样本**」，其余可为治理抓手 / 惠民增收 / 税源本地化 / 风险可管。
- 每卡给一个可观测的指标，不要形容词。

### 捌 试点路径

- 三阶段，每阶段：目标 → 动作 → **硬性关卡（不达标即停）** → 时长。
- 关卡必须是可测的（准确率、覆盖率、投诉率、处置时效），不能是「运行良好」。

### 玖 合规红线 + 政策诉求

- ⛔ 自我设限清单（建议 6–8 条），每条写成「我们不做 X，因为 Y；触发 Z 时停」。
- 政策诉求卡：编号 + 诉求 + 对接部门 + 时间窗口 + 「给了之后我们承担什么」。
- 结尾一句免责：制度未落地环节以国家制度演进为前提，本方案不承诺制度结果。

## 公文格式层（GB/T 9704 口径）

材料如果要作为**公文附件**报送，格式按 GB/T 9704《党政机关公文格式》的骨架走；作为**申报材料**（非正式公文）时，不必套红头，但保留同样的秩序感：

| 元素 | 要求 |
|---|---|
| 标题 | 发文机关 + 事由 + 文种（如「关于……试点的请示/方案」），不用问句、不用营销词 |
| 主送机关 | 顶格，全称或规范化简称 |
| 正文层次 | 一、（一）1.（1），**层级符号不跨级混用** |
| 数字 | 成文日期、数量、比例用阿拉伯数字；序数、成语、惯用语用汉字 |
| 附件 | 另页起，「附件：1. ……」逐条列出 |
| 落款 | 单位全称 + 成文日期，日期用「2026 年 10 月 30 日」不缩写 |
| 页边距/字体 | 正式公文：上 3.7cm 下 3.5cm 左 2.8cm 右 2.6cm，正文三号仿宋 |

只做格式层，不代替公文写作规范审查；如果项目里已有公文排版工具（如 gongwen 类 skill），把本 skill 的**内容骨架**与它的**格式渲染**组合使用，不要重复实现排版。

## 禁词与检查（交付前必跑）

```bash
# 1) 商业竞品名不得出现在政务材料正文（0 次）
grep -n -i '竞品A\|竞品B\|boss\|zhipin\|freelancer' out.html
# 2) 占位符残留
grep -n 'TODO\|TBD\|待补\|待写\|\[\[.*\]\]' out.html
# 3) 无指向的政策表述
grep -n '高度重视\|大力支持\|政策利好' out.html
# 4) 数字口径：同一指标是否两个数
#    全文抽出数字，按「单位 + 上下文」人工核一遍（不要只看总数）
```

命中处逐条裁决：用户给的**公开口径参照**可以保留（如某省政务平台的公开数据），**商业竞品名**必须清零。

## 三版叙事地基（换版 = 全文重写）

同一项目常被要求换地基，每换一次都是重写，不是局部改：

1. **平台底座版**：借成熟平台证明模式可行。弱点：政府会问「平台这么成熟，为什么还需要你们」。
2. **从零成长版**：从零培育本土主体。政策诉求从锦上添花变成雪中送炭，但必须补一章「为什么扶持从零主体」（论证独立第三方位是制度空白）。
3. **全行业版**：单场景升维为基础设施。必须补「价值回流」命题（数据单向流出图 + 回流三通道 + 一本账），并给先行案例清单（空白点即定位）。

## 常见翻车

- 政策文号写错年份或机关（最伤专业度）。
- 九章写成了十一个「优势」，没有一章写风险。
- 技术架构图里没有监管接口层。
- 试点阶段没有停止条件，等于要求无限期投入。
- 政策诉求混在正文里，评审找不到「你到底要什么」。
