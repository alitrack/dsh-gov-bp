# 九章逐章检查表

逐章勾：**必答项是否都在**、**证据是否可核**、**有没有把优势写成风险缺失**。

## 壹 政策依据与时代窗口
- [ ] 4 张政策卡，每卡带文号 + 施行日期
- [ ] 每卡一句「它开了什么口子」
- [ ] 收尾给出窗口期判断（为什么是现在）
- [ ] 文号一手核过，核不到的标「未核到」

## 贰 要解决的问题
- [ ] 需求侧痛点（谁被卡住，卡在哪一步）
- [ ] 供给侧缺口（为什么现在没人做）
- [ ] 若有灰色替代：用「阳光化」治理逻辑写，不写「禁止需求」

## 叁 方案总览
- [ ] 流程图 ≤5 个节点，每节点「谁做/做什么/产出什么」
- [ ] 闭环条：数据或凭证如何回流（单向流出＝没闭环）

## 肆 核心机制
- [ ] 分级表（绿/金/红或等价三档）
- [ ] 每档：准入条件、数据范围、审批动作、退出条件
- [ ] 对齐已有标准编号（分类分级、个保相关国标）

## 伍 成长路径
- [ ] 阶梯图，每级有单边独立价值
- [ ] 明确「只走到这一级也成立」

## 陆 技术架构
- [ ] 分层色块（接入/处理/存储/服务/监管）
- [ ] **监管接口层**：看板 + 审计取证 + 红线熔断
- [ ] 数据流与权限边界画清

## 柒 政府价值
- [ ] 3–4 张价值卡，第一张是「可复制改革样本」
- [ ] 每卡带可观测指标，不写形容词

## 捌 试点路径
- [ ] 三阶段：目标/动作/关卡/时长
- [ ] 每阶段关卡可测，且写明「不达标即停」
- [ ] 验收流程：初验 → 试运行 → 终验；交付物清单

## 玖 合规红线 + 政策诉求
- [ ] 6–8 条自我设限（不做 X，因为 Y，触发 Z 停）
- [ ] 诉求卡：编号 + 诉求 + 对接部门 + 时间窗口 + 承担什么
- [ ] 免责句：制度未落地环节以国家制度演进为前提

# 自我设限清单模板（挑 6–8 条，按项目改）

```
1. 不采集与试点目标无关的个人信息。
2. 不向第三方提供原始数据，只提供加工结果。
3. 不接入未完成安全评估的模型或外部服务。
4. 不在未取得书面授权的情况下收录受著作权保护的标准全文。
5. 不处理涉密数据（涉密场景另立项目、另行资质）。
6. 准确率低于 __ 时停止扩面，回到上一阶段整改。
7. 出现 __ 类投诉超过 __ 起时，暂停并向主管部门报告。
8. 试点期满未达关卡指标，不申请延续，主动结项并公开结论。
```
